> 本文已根据 2026 年 7 月 27 日发布的 Kimi K3 Technical Report、Hugging Face 模型卡与模型配置更新。

Kimi K3 是月之暗面发布的开放权重原生多模态 Agent 模型。其研究目标是在统一模型中协同扩展预训练容量、长上下文建模与测试时计算；具体模型规格见下表。

与仅增加参数规模的扩展路线不同，K3 将模型架构、后训练与基础设施作为相互依赖的整体，考察它们如何共同支持长程推理和多步工具交互。下文依次讨论其架构设计、训练方法与系统实现。

| 项目 | Kimi K3 |
|------|---------|
| 架构 | 稀疏 Mixture-of-Experts |
| 总参数 / 激活参数 | 2.78T / 104.2B（模型卡取整为 2.8T / 104B） |
| Transformer 层数 | 93，其中 1 层为 Dense Layer |
| 隐藏维度 | 7,168 |
| 注意力组成 | 69 层 KDA + 24 层 Gated MLA |
| 注意力头 | 96，head dimension 为 128 |
| AttnRes | 8 个模型 block，block size 为 12；最后一个 block 只有 9 层 |
| LatentMoE | latent dimension 3,584；每个 routed expert 的 hidden dimension 为 3,072 |
| 专家配置 | 896 个 routed experts，每个 token 选择 16 个；另有 2 个 shared experts |
| 词表 | 163,840（官方表格取整为 160K） |
| 上下文窗口 | 1,048,576 token |
| 激活函数 | SiTU-GLU |
| 视觉编码器 | MoonViT-V2，401M 参数、27 层、12 heads、patch size 14 |
| 量化 | routed expert 权重 MXFP4、输入激活 MXFP8；非专家组件保留较高精度 |
| 模态 | Hugging Face 标注文本与图像输入、文本输出；技术报告还描述了视频训练与理解 |

## 总体架构：同时扩展序列、深度与宽度

K3 把主干划分为重复的 Hybrid Attention block。每个 block 依次放置 3 层 KDA 和 1 层 Gated MLA，形成 3:1 的线性注意力 / 全局注意力混合；主干末尾再增加一层 Gated MLA，保证最后一层执行全局内容交互。每个 attention layer 后都连接一个 Stable LatentMoE。

这几组组件各自解决不同瓶颈：

- **序列方向**：KDA 用固定尺寸的递归状态压缩历史，Gated MLA 周期性恢复无约束的全局 token-to-token 交互。
- **深度方向**：AttnRes 让当前层按 token 选择此前 block 的表示，不再只能接受固定求和后的单一残差流。
- **宽度方向**：Stable LatentMoE 让 896 个 routed experts 在较窄的 latent space 中工作，每个 token 激活 16 个专家；full-width shared experts 处理公共变换。
- **视觉方向**：MoonViT-V2 将图像和视频编码后投影到语言模型的共享 embedding space，与文本共同进入同一主干。

## Hybrid Attention

### Kimi Delta Attention

KDA 不为每个历史 token 保存一份完整的 key 和 value，而是为每个 head 维护矩阵状态：

$$
S_t\in\mathbb{R}^{d_k\times d_v}
$$

在单个 head 中，KDA 先按 key channel 衰减旧状态，再用 delta rule 写入当前关联：

$$
S_t=
\left(I-\beta_t k_tk_t^\top\right)
\operatorname{Diag}(\alpha_t)S_{t-1}
+\beta_t k_tv_t^\top,
\qquad \widetilde{o}_t=S_t^\top q_t
$$

其中 $\alpha_t\in(0,1)^{d_k}$ 是逐通道 retention factor，$\beta_t\in(0,1)$ 控制写入强度。把它展开可以更直观地看到 delta rule：

$$
\widetilde{S}_{t-1}=\operatorname{Diag}(\alpha_t)S_{t-1}
$$

$$
\widehat{v}_t=\widetilde{S}_{t-1}^{\top}k_t,
\qquad
S_t=\widetilde{S}_{t-1}+\beta_tk_t(v_t-\widehat{v}_t)^\top
$$

状态只写入旧记忆对当前 value 的预测误差：已经记住的关联不会被重复累加，过时关联则可以被纠正。由于 $S_t$ 的尺寸与上下文长度无关，KDA 层的状态不会随 token 数线性增长。

K3 相比公开的 Kimi Linear 参考实现又做了三处关键修改。

#### 1. 有下界的 log-decay

Kimi Linear 使用无下界的 negative Softplus。长 chunk 内的累计衰减可能非常小，计算 reciprocal rescaling 时容易超出有限精度范围。K3 改为：

$$
g_t^h=g_{\min}\operatorname{Sigmoid}\!\left(e^{A^h}z_t^h\right),
\qquad
\alpha_t^h=\exp(g_t^h),
\qquad g_{\min}=-5
$$

因此每步 retention factor 都大于 $e^{-5}$。在 16-token secondary tile 中，累计 log-decay 被限制在 $(-80,0)$，reciprocal 仍位于 BF16 的动态范围内。K3 因而可以让 diagonal 与 off-diagonal causal tiles 都使用稠密 Tensor Core 矩阵乘法，移除 Kimi Linear 中较慢的 position-pair diagonal path。

#### 2. Full-rank 输出门

K3 将 KDA 的低秩输出门改为输入相关的 full-rank projection：

$$
y_t=W_o\left[
\operatorname{Sigmoid}(W_gx_t)
\odot
\operatorname{RMSNorm}(\widetilde{o}_t)
\right]
$$

门控可以让每个 token 独立决定读取哪些输出 channel。Query、key 和 value 投影还会经过 ShortConv 与 Swish；query 和 key 额外进行 L2 normalization。

#### 3. 与 NoPE Gated MLA 混合

KDA 擅长固定状态的长序列 mixing，但会压缩历史；MLA 则缓存低秩 KV latent，保留全局内容交互。K3 每 3 层 KDA 插入 1 层 Gated MLA，并让全部 MLA layer 使用 NoPE。位置和近因偏置主要由 KDA 的递归门控隐式表达，因此把上下文扩展到 1M 时不需要调整 RoPE frequency base 或做插值。

需要注意：**K3 是 KDA-MLA 混合模型，不是所有层都没有 KV cache**。KDA recurrent state 为固定尺寸，MLA KV cache 仍随序列增长；推理系统必须同时管理两种状态。

## Attention Residuals

标准 PreNorm Transformer 将此前所有层压入一个累积状态：

$$
h_l=h_1+\sum_{i=1}^{l-1}f_i(h_i)
$$

深度增加后，新层输出在累积状态中的相对占比会下降。AttnRes 把固定求和改为沿深度方向的 attention。对第 $l$ 层，embedding 与此前层输出同时作为 key 和 value：

$$
k_i=v_i=
\begin{cases}
h_1,& i=0\\
f_i(h_i),&1\le i\le l-1
\end{cases}
$$

$$
\alpha_{i\rightarrow l}
=
\frac{\exp\left(w_l^\top\operatorname{RMSNorm}(k_i)\right)}
{\sum_{j=0}^{l-1}\exp\left(w_l^\top\operatorname{RMSNorm}(k_j)\right)},
\qquad
h_l=\sum_{i=0}^{l-1}\alpha_{i\rightarrow l}v_i
$$

$w_l$ 是 layer-specific learnable pseudo-query。权重按 token 计算，因此不同 token 可以从不同深度检索特征。

Full AttnRes 的计算在不足 100 层时可接受，主要问题是保存全部 layer output 所需的 $O(Ld)$ memory 和 pipeline communication。Block AttnRes 把连续层先在 block 内求和，只在 block 间做 attention，把状态降为 $O(Nd)$。K3 采用 8 个模型 block、block size 12：前 7 个 block 各含 12 层，最后一个 block 含 9 层；连同始终可检索的 embedding，共有 9 个 block-level source。

## Stable LatentMoE

K3 的 full model width 为 7,168，routed expert 则在 3,584 维 latent space 中工作。对输入 $x\in\mathbb{R}^d$，routed path 先降维、路由，再升回 full width；两个 shared experts 始终处理原始 full-width 输入：

$$
u=\sum_{i\in T_k(x)}p_iE_i^{\mathrm{routed}}(W_\downarrow x)
$$

$$
y=
\sum_{j=1}^{2}E_j^{\mathrm{shared}}(x)
+W_\uparrow\operatorname{RMSNorm}(u)
$$

每层有 896 个 routed experts，每个 token 选择 16 个，相当于在 routed expert pool 中使用 $1/56$。这并不等于整个模型只激活 $1/56$ 参数，因为 shared experts、attention、latent projections 和其他组件仍会执行；官方统计的实际激活参数为 104.2B。

如此高的稀疏度会放大两类问题：连续矩阵乘法造成 routed branch activation 爆炸，以及近千个专家的负载难以稳定平衡。Stable LatentMoE 用三个组件处理它们。

### Normalized LatentMoE

在 routed experts 聚合与 $W_\uparrow$ 之间插入 RMSNorm，降低不同专家和路由权重造成的尺度波动。报告称这一改动同时改善训练稳定性、validation loss 和下游评测。

### SiTU-GLU

作为参照，SwiGLU 以 Swish 作为 gate branch，并与线性的 up branch 逐元素相乘：

$$
\mathrm{SwiGLU}(x)
=
\left[(W_gx)\odot\sigma(W_gx)\right]
\odot(W_ux).
$$

其 gate 与 up branch 都无上界，低精度训练中容易产生 activation outlier。K3 的 Sigmoid Tanh Unit GLU（SiTU-GLU）分别以 scaled tanh 对两个线性因子做 smooth cap：

$$
\begin{aligned}
\text{SiTU-GLU}(x)
&=
\left[
\beta_1\tanh\!\left(\frac{W_gx}{\beta_1}\right)
\odot\sigma(W_gx)
\right] \\
&\quad\odot
\left[
\beta_2\tanh\!\left(\frac{W_ux}{\beta_2}\right)
\right].
\end{aligned}
$$

  <img src="{{ '/assets/images/kimi-k3/situ-glu-comparison.png' | relative_url }}" alt="GLU、SwiGLU 与 SiTU-GLU 的 gate branch、up branch 和标量响应曲线对比">
  <figcaption>GLU、SwiGLU 与 SiTU-GLU 的分支定义及标量响应。SiTU-GLU 在原点附近跟随 SwiGLU，并在大正值区域趋近上界。图源：Kimi K3 技术报告，图 4。</figcaption>
</figure>

K3 取 $\beta_1=4$、$\beta_2=25$。scaled tanh 在原点附近近似线性，因而 SiTU-GLU 保留 SwiGLU 的局部响应；同时，$\lvert\tanh(z)\rvert<1$ 且 $0<\sigma(z)<1$，故每个输出坐标满足 $\lVert\text{SiTU-GLU}(x)\rVert_\infty\le\beta_1\beta_2=100$。

### Quantile Balancing

K3 使用 auxiliary-loss-free routing：expert-specific bias 只影响 Top-k dispatch，不参与最终 mixture weight。传统固定步长 bias update 在 896 个专家上会遇到“适应慢”与“负载振荡”的权衡。

Quantile Balancing（QB）改为从 router-score margin 的分位数直接估计每个 expert bias，使目标负载等于 $mk/n$。实际训练不会收集数百万个 margin 做精确 quantile，而是为每个专家汇总 histogram，通过一次 all-reduce 合并 bin count；推理时冻结最终 bias。

## 原生视觉：MoonViT-V2

K3 不是在语言模型训练结束后再接入视觉塔。文本、图像与视频从预训练开始就在统一 next-token prediction objective 下联合优化，视觉 feature 经轻量 MLP projector 进入共享 embedding space。

MoonViT-V2 是约 401M 参数的 27 层 Vision Transformer，使用 RMSNorm，并移除 linear / attention projection 的 bias。与 Kimi K2.5 使用 SigLIP initialization 不同，K3 的视觉编码器完全从头训练。报告中的 ablation 显示，它相对 SigLIP-initialized MoonViT-3D 具有更低、更少尖峰的 gradient norm，同时在视觉评测中达到相当结果。

图像与视频共享参数：attention 分为 frame 内 spatial pass 和 frame 间 temporal pass，并用 temporal pooling 压缩视频 token。投影前的 $2\times2$ pixel shuffle 令视觉 token 数减少四倍，使最高 $3584\times3584$ 的输入仍能放入 1M 上下文。

Hugging Face 模型卡当前将发布模型标为 `Image-Text-to-Text`，汇总表中的模态为 Text / Image；视频能力的描述来自技术报告。部署时应以所用 processor 与 serving engine 的实际接口支持为准。

## 预训练与 1M 上下文

### 数据与训练 recipe

预训练文本覆盖 Web Text、Code、Mathematics 和 Knowledge 四个主域，视觉语料覆盖 caption、交错 image-text document、OCR、perception、video 与 visual coding。Visual coding 数据包括 SVG、3D asset、网页、游戏与 CAD schematic 的代码和渲染结果。

训练使用 Per-Head Muon、Kimi K2 的 weight clipping、Quantile Balancing，以及带 1% linear warmup 的 cosine learning-rate schedule；weight decay 为 0.1。Per-Head Muon 将 Q、K、V projection 的 momentum matrix 按 head 分块做 Newton-Schulz orthogonalization，避免大 head 的尺度主导共享更新，并略微减少优化器开销。

报告公开了模型尺寸、context curriculum 与数据类型，但**没有披露预训练总 token 数和各数据域的精确比例**。

### 四阶段长上下文扩展

K3 使用 NoPE，不需要为 1M 上下文修改 positional encoding。Context window 按四阶段逐步扩展：

1. 预训练从 8K 开始；
2. 预训练后续阶段扩展到 64K；
3. cooldown 阶段进入 256K；
4. cooldown 最终扩展到 1M。

长文档和长视频先经过 exact / fuzzy deduplication、video frame perceptual hashing、质量过滤与结构校验。由于自然长样本稀缺，训练还会重排并拼接多模态文档和子任务，让答案必须依赖分散在整个长上下文中的信息。昂贵的长序列计算只占整体训练预算的一小部分。

### K2 到 K3 的规模变化

| 项目 | Kimi K2 | Kimi K3 |
|------|---------|---------|
| 层数 | 61 | 93 |
| 总参数 | 1.04T | 2.78T |
| 激活参数 | 32.6B | 104.2B |
| Routed experts / token | 384 / 8 | 896 / 16 |
| Attention heads | 64 | 96 |
| 训练上下文 | 128K | 1M |
| 注意力 | 61 MLA | 69 KDA + 24 Gated MLA |
| 激活函数 | SwiGLU | SiTU-GLU |

Scaling-law 拟合显示，架构、数据与训练改进的组合相对 K2 获得约 2.5 倍 overall scaling efficiency。

## 后训练：从九个专家策略蒸馏为一个模型

K3 的 post-training 分为三个阶段。

### 1. Supervised Fine-Tuning

SFT 用此前 Kimi 系列的领域模型合成长程 Agent trajectory，再经过多阶段验证与 human-in-the-loop annotation。复杂交互统一序列化为 XTML（eXtensible Token Markup Language）chat template。MXFP4 / MXFP8 的 Quantization-Aware Training 从这一阶段开始，而不是训练结束后再做纯 PTQ。

### 2. Reinforcement Learning

RL 覆盖三个域：

- general tasks：通用体验、视觉、推理、faithfulness、搜索和知识工作；
- general agents：长程助手、deep research 和长篇写作；
- coding agents：软件工程、coding experience、GPU kernel 和 web development。

每个域分别训练 low、high、max 三档 reasoning effort，共得到九个 expert policies。Reasoning-effort RL 为每道题设置 token budget：超过相对预算的 trajectory 会被惩罚，随后逐步收紧 budget multiplier，得到 high 与 low policy。对 Agent 任务，预算同时统计 reasoning、tool-call argument 和累计输出 token。

长程 trajectory 的尾延迟很大。K3 使用 partial rollout：每轮只等待一定比例的 rollout 完成，其余 trajectory 暂停并在后续 iteration 恢复。对不可直接验证的通用任务，Agentic Generative Reward Model 会先读结果、生成 rubric、逐项评分并写入 scorepad；额外的长度预算用于抑制通过冗长输出来 reward hacking。

### 3. Multi-Teacher On-Policy Distillation

MOPD 在训练时随机选择 domain 与 effort，由对应的九个 teacher 之一给统一 student 提供 dense per-token reward。这样既保留领域能力，也让同一个发布模型通过 `reasoning_effort` 切换 low、high 和 max。

后训练还面向部署做了两项设计：

- routed expert weights 在 SFT 与 RL 全程使用 MXFP4，expert input activation 使用 MXFP8；rollout 与训练保持相同 quantization scheme，减少 train-inference mismatch；
- 预训练的 MTP layer 被微调为 EAGLE-3-style draft model，融合第 1、第 4 与最后一个 AttnRes block 的低、中、高层 feature，用于 lossless speculative decoding。

### 不绑定单一 Agent harness

固定 harness 容易让模型过拟合 tool schema、system prompt 或 context management。K3 的 white-box RL environment 将 tool interface、prompt、skill、memory、subagent 与 context strategy 做成可组合模块，可构造 Kimi Code、Claude Code、Codex、OpenClaw、Hermes 等不同 scaffold。训练任务包括可验证搜索、专业知识工作、视觉推理、kernel optimization、跨多日 personal assistant、Autonomous Execution Task 与 web development。

## 基础设施

2.8T MoE、Hybrid KDA-MLA 与 1M-token Agent trajectory 会同时触发计算、通信、显存、cache 和 sandbox 生命周期问题。报告给出的主要系统设计如下。

| 场景 | 设计 |
|------|------|
| KDA 训练 / prefill | FlashKDA 将 chunk 内并行计算与跨 chunk state propagation 重叠；长 prefill 还可在单卡 SM 间做 context parallelism |
| 跨设备长上下文 | KDA Context Parallelism 将每段表示为“局部生成状态 + 作用于输入状态的累计 transition”，以 fixed-size all-gather 和 prefix scan 精确合并 |
| 3T-class MoE 预训练 | MoonEP 在线规划与迁移 redundant experts，让每个 rank 接收完全相同的 token 数；静态 shape 消除逐层 host synchronization，并支持 zero-copy dispatch / combine |
| 显存管理 | Activation recomputation、FP8 quantization、CPU / remote offload 可按 tensor 组合；Pipeline ZeRO-2 将 gradient shard 放到 CPU；Muon 只点对点拉取本 rank 所需参数 shard |
| 多模态编码器 | 大图和长视频做 Dynamic Context Parallelism；多数 ViT 计算被安排进 Pipeline Parallelism bubble |
| 1M-token Agent RL | GPU 外的 CPU DRAM KV cache pool 保存被驱逐 prefix；training state 在 rollout 前后转移到 NVMe；auto-throttling scheduler 随 cache pressure 调整并发 |
| Sandbox | AgentENV 基于 Firecracker microVM，支持 pause / resume、fork、snapshot 与增量 checkpoint |
| 在线推理 | KDA state 与 MLA KV 共用 paged pool；专用 KDA、Block AttnRes、LatentMoE kernel 配合 cache-aware affinity 和 budget-based admission control |

KDA Context Parallelism 的通信量由固定尺寸 recurrent state 决定，而不是随 token 数增长的 KV block；其 compute 随 context-parallel rank 近似线性扩展。MoonEP 则以每个 rank 最多 $E/R$ 个 redundant expert slot 保证存在平衡方案，避免训练因无可行 dispatch plan 而中断。

AgentENV 的报告数据也体现了 Agent RL 的规模：incremental checkpoint 与 resume 最低分别达到 133 ms 和 49 ms，真实 workload 中 memory overcommit 最高为 6.5 倍；K3 训练与评测累计创建了 51,219,741 个 sandbox，涉及 1,505,678 个 sandbox image。

### Hybrid prefix cache

KDA state 是每个 request 一份的大矩阵，MLA KV 则按 token 增长。若 hash granularity 直接等于保存 KDA checkpoint 的 physical block，block size 会被迫放大到 1,024 至 6,144 token，短 prefix 基本无法命中。

K3 将二者解耦：MLA 在 physical page 内以更细的 hash block（报告示例为 512 token）登记 prefix，KDA 只在部分 hash endpoint 保存 state checkpoint。Cache hit 必须同时找到 MLA prefix 与所有 KDA group 的 checkpoint；命中后复制为 request-private running state，再继续 prefill。这样可以在 512-token boundary 复用 prefix，而不要求命中 physical block 边界。

## 开放权重、量化与部署

Hugging Face 仓库发布了完整权重、config、processor 与 custom modeling code。截至本文更新时，仓库文件总量约 1.56 TB，主权重拆成 96 个 Safetensors shard。如此体积来自原生 MXFP4 expert weights；若按纯 BF16 保存 2.78T 参数，体积还会显著更大。

量化并非覆盖全部模块。技术报告明确指出，routed MoE expert weights 使用 MXFP4、其输入 activation 使用 MXFP8；attention projection、latent MoE projection、shared experts、router 等非专家组件保留较高精度。Hugging Face `config.json` 也通过 `compressed-tensors` 配置排除了这些模块。

官方模型卡推荐以下 serving engine：

- vLLM；
- SGLang；
- TokenSpeed。

Transformers 示例需要 `trust_remote_code=True`。这只是加载接口，不代表 1.56 TB 模型可以在普通单机上运行；实际部署仍需要大规模 expert parallelism、高带宽互联、足够的聚合显存与针对 KDA / LatentMoE 的 engine support。

### Thinking 与多轮消息

K3 始终启用 thinking，并返回 `reasoning_content`。API 顶层字段 `reasoning_effort` 支持 `low`、`high`、`max`，默认值为 `max`。

模型以 preserved thinking history mode 训练。多轮对话或 tool call 中，下一轮必须把 API 返回的完整 assistant message 原样放回 `messages`，包括 `reasoning_content`、`content` 和 `tool_calls`。只保留最终答案会丢失模型训练时依赖的状态，降低后续一致性。
